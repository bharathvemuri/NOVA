## Work mapped to the plan

### S1 — ignore generated declaration output

- `.gitignore`: added `dist-types/` alongside the existing `dist/` entry.
  `.prettierignore` and `eslint.config.js` already excluded it (confirmed by
  inspection), so this closes the one remaining gap.
- Verified `apps/web/dist-types/` is build output only (`main.d.ts`,
  `main.d.ts.map`, `app/`), regenerated by `pnpm typecheck`/`pnpm build`, not
  hand-authored source — consistent with treating it as ignorable.
- Note: this environment's `.git` metadata points at a Windows host path
  (`gitdir: C:/Users/.../\.git/worktrees/T-001`) that does not exist inside
  this container, so no `git` command (including `git rm --cached`,
  `git status`) is runnable here to confirm nothing under `dist-types/` was
  previously tracked. The `.gitignore` entry itself is in place; if the
  harness's commit layer finds tracked files under `apps/web/dist-types/` it
  should untrack them with `git rm -r --cached apps/web/dist-types`, per the
  plan's fallback instruction.

### S2 — close the devDependency gap in the boundary checker

- `scripts/check-boundaries.mjs`:
  - `loadWorkspaceManifests` now reads and returns `devDependencies` and
    `peerDependencies` alongside `dependencies` for every manifest (previously
    only `dependencies` was read).
  - `closureOf` takes an `includeDevAndPeer` flag. Rules 1–2 (forbidden
    externals for `packages/astronomy` and `packages/renderer`) now call it
    with `includeDevAndPeer: true`, so a forbidden package hidden in
    `devDependencies` or `peerDependencies` is caught, not just one in
    `dependencies`.
  - Rule 3 (packages → apps) and rule 5 (cycle detection) intentionally keep
    walking `dependencies` only — the plan scopes the devDependency union to
    rules 1–2, and rule 5 is explicitly the *production*-dependency graph.
  - Rule 4 (zod) is untouched: still checks `dependencies` only, since a
    dev-time zod is not a shipped contract.
- `tests/boundaries/boundaries.spec.ts`: added
  `'detects a forbidden external hidden in devDependencies (AC 7)'`, a
  synthetic `@nova/astronomy` manifest with `devDependencies: { three: '*' }`
  and empty `dependencies`, asserting `evaluate()` reports the violation.
  Confirmed red-before/green-after by temporarily reverting the source change
  and re-running `pnpm test` (failed as expected), then reapplying and
  re-running (passed) — see Commands run.

### S3 — deep-subpath hardening for the import-level lint

- `eslint.config.js`: extended the three `no-restricted-imports` `group`
  arrays to include `@nova/renderer/*`, `@nova/web/*`, `@nova/api/*` alongside
  the existing bare package names, in the `packages/astronomy/**`,
  `packages/renderer/**`, and `packages/**` (apps-boundary) blocks
  respectively. `pnpm lint` (ESLint + Prettier) passes unchanged.

### S4 — document the local E2E precondition

- `README.md`: expanded the `pnpm test:e2e` bullet under "Testing" to state
  that Playwright's `webServer` runs `vite preview` against `apps/web/dist`,
  so `pnpm build` must run first on a clean checkout
  (`pnpm build && pnpm test:e2e`). Chose documentation over changing the
  `test:e2e` script itself, since `.github/workflows/ci.yml`'s `e2e` job
  already runs `pnpm build` before `pnpm test:e2e` (lines 75–82) — the gap was
  only in local/undocumented usage, not in CI.
