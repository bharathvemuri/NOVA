## Context

002 §14 requires perturbation code isolated by model/body and forbids hidden correction terms — this is the single highest-risk area for AI-generated numerical code, which is why 005 §8 mandates independent validation later. Accuracy is not asserted here; it is measured in the validation phase against Horizons fixtures.

## Task

Implement the seven major-planet models under SCHLYTER_PLANETS_V1 using the shared elliptic pipeline, with each body's perturbation corrections in its own module. Cite every equation and constant. Add per-body unit tests using tutorial worked examples and physical plausibility bounds. Do not tune constants to make any test pass, and do not claim accuracy — validation happens in a separate task by a different agent.

## Acceptance criteria

- [ ] All seven bodies return heliocentric ecliptic Cartesian positions and distances in AU with modelId SCHLYTER_PLANETS_V1
- [ ] Perturbation corrections are implemented for the bodies the tutorial specifies (Jupiter, Saturn, Uranus) and are isolated in per-body modules rather than inlined into the shared pipeline
- [ ] Each correction term documents: its source reference and tutorial section, its mathematical form, its stated validity range, and has at least one test asserting the correction is actually applied (result differs from the unperturbed result by the expected order of magnitude)
- [ ] No hidden or undocumented correction terms exist; a reviewer can map every constant in the code to a line in the cited source
- [ ] Saturn's ring-free, body-centre position is what is computed; no visual or apparent-magnitude logic appears
- [ ] Each body's output is tested against the tutorial's worked example values where the tutorial provides them, and against internal plausibility bounds (heliocentric distance within the body's known perihelion/aphelion range) across sampled dates spanning 1900–2100
- [ ] Determinism and purity tests pass for every body
- [ ] No cross-body coupling: computing Mars does not require computing Jupiter
