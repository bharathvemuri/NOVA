## Context

Newton-Raphson is acceptable for V1 provided difficult cases are handled safely (002 §12). Pluto and high-eccentricity element sets stress the solver, so the high-e cases are not optional. 005 §10 forbids silently substituting an approximation on failure; hence the explicit error path.

## Task

Implement the elliptic Kepler solver in packages/astronomy/src/math with a deterministic initial estimate, iteration to a documented tolerance, an enforced maximum iteration count and explicit convergence metadata. Cite the equation M = E − e·sin(E) and the source in the module documentation. Add the numerical stability tests from 006 §16 relevant to anomaly handling.

## Acceptance criteria

- [ ] Solver signature accepts mean anomaly in radians and eccentricity, normalizes the mean anomaly internally, and returns eccentric anomaly plus convergence metadata (iterations used, achieved residual, converged flag)
- [ ] Convergence tolerance and maximum iteration count are named exported constants with documented rationale, not inline magic numbers
- [ ] When the maximum iteration count is reached without meeting tolerance, the solver throws NumericalConvergenceError identifying the failing operation and the input eccentricity/mean anomaly, and never returns a partially converged value as if it had succeeded
- [ ] Residual test: for every tested case, |E - e·sin(E) - M| is below the documented tolerance
- [ ] Tests cover near-circular (e≈0), moderate, and high eccentricity (at least e=0.9 and e=0.97), perihelion and aphelion, M=0, M=π, M=2π, negative M, and M far outside [0,2π)
- [ ] Solver is deterministic: the same inputs produce bit-identical output across runs, and it uses no global mutable state, no randomness and no wall-clock time
- [ ] A fixed-iteration-count implementation without convergence checking is not used
