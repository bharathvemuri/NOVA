## Context

These are the lowest-level primitives; nearly every later astronomy task consumes them. 002 §7 is explicit that the astronomy package owns its own vector type and must not import Three.js (ADR-001, ADR-010). Angles are radians internally per 002 §5, with degree conversion at the boundary only.

## Task

Implement the angle utilities and the immutable Vector3 type in packages/astronomy/src/math, with unit conventions documented in code. Cover the normalization edge cases enumerated in the domain spec and add the mathematical property tests from 006 §4. Define and document the behaviour of degenerate inputs (zero vector normalization, non-finite inputs) rather than letting them produce NaN silently.

## Acceptance criteria

- [ ] Angle module exports normalizeRadians0To2Pi, normalizeRadiansMinusPiToPi, degreesToRadians, radiansToDegrees, hoursToRadians, radiansToHours
- [ ] Normalization is tested for zero, positive overflow, negative overflow, exact 2π, and very large magnitudes in both directions, with documented behaviour at each boundary
- [ ] Vector3 is an immutable value type { x, y, z } with add, subtract, scale, magnitude, normalize, dot, cross and distance; every operation returns a new value and no operation mutates its arguments (asserted by test)
- [ ] normalize of a zero-length vector has explicitly defined, tested behaviour rather than producing NaN silently
- [ ] Property tests cover at minimum: normalize(normalize(x)) === normalize(x) for angles, magnitude(scale(v,k)) ≈ |k| * magnitude(v), and dot/cross identities, with documented tolerances
- [ ] Three.js is not imported anywhere in the module and a test or lint rule proves it
- [ ] Numeric precision assumptions (double precision, no arbitrary-precision arithmetic) are documented in the module header
