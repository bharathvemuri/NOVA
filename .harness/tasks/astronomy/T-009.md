## Context

This is the shared machinery every elliptic body model reuses, factored out so Mercury–Neptune, Pluto and (partly) the Moon do not each reimplement the chain. 001 §14 wants the pipeline represented explicitly in code rather than hidden inside one calculatePlanetPosition() function. Perturbations are deliberately excluded here and isolated per body/model per 002 §14.

## Task

Implement the generic elliptic-orbit pipeline in packages/astronomy/src/models plus the typed representation of Schlyter's time-varying element tables. Keep each stage a separately callable, separately tested function. Cite the source equations. Do not implement any body's perturbation corrections in this module and do not add body-specific branching.

## Acceptance criteria

- [ ] The pipeline is expressed as discrete, individually exported and individually tested stages matching 002 §11: day number → time-dependent elements → mean anomaly → normalized anomaly → eccentric anomaly → true anomaly and radius → orbital-plane coordinates → ecliptic orientation transform → heliocentric state
- [ ] Time-varying elements are stored as base value plus rate coefficient per element and evaluated at the requested day number; no element table stores a precomputed single-epoch value where the tutorial gives a rate
- [ ] Every equation in the module cites the corresponding section of Schlyter's tutorial in a comment
- [ ] Units are declared at every stage (degrees in the source tables converted once to radians at ingest; AU for distances)
- [ ] Intermediate-stage unit tests use hand-computed or tutorial-sourced values, not values produced by the code under test
- [ ] The pipeline is a pure function: same elements + same instant → bit-identical state, verified by test
- [ ] The pipeline throws NumericalConvergenceError unchanged from the Kepler solver rather than substituting a fallback value
- [ ] No body-specific perturbation logic lives in this module
