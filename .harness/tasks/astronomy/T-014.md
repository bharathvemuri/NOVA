## Context

The answered questions kept precession as a shipped public API even though no V1 frame consumes it, and separately require the validation harness to use its own higher-fidelity precession (IAU 1976 matrix) rather than this one — so this module must be honest about its limitations to avoid a future agent wiring it into the fixture comparison.

## Task

Implement Schlyter's simple precession as a public transformation in the coordinates subsystem, with explicit from/to epochs, documented model and validity range, and tests for identity, round-trip and century-scale magnitude. Document prominently that it is longitude-only and is not the transformation used by the validation harness. Keep it out of every body model.

## Acceptance criteria

- [ ] precess(state, fromEpoch, toEpoch) is exported from packages/astronomy and operates on a CelestialState, returning a new state with its epoch/frame annotation updated and the input left unmutated
- [ ] The implementation uses Schlyter's simple precession formulation, cited, with the module documenting explicitly that it is a longitude-only correction that does not model the rotation of the ecliptic plane itself
- [ ] The supported model name and validity range are documented in the module header and in docs/astronomy
- [ ] Round-trip test: precessing from epoch A to B and back to A returns the original state to a documented tolerance
- [ ] A zero-interval precession (fromEpoch === toEpoch) is an exact identity
- [ ] Magnitude test: precession over one century shifts ecliptic longitude by approximately the expected ~1.4°, asserted within a documented tolerance
- [ ] Documentation states that no V1 reference frame consumes this transformation at runtime and that it exists for future J2000-suffixed frames and for reasoning about epochs
- [ ] Precession logic appears in no body model
