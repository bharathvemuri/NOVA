## Context

This is the single dispatch point 001 §8 asks for instead of a giant calculatePlanetPosition(). The answered questions fixed the degenerate-case behaviour precisely: zero vector, distance zero, and sphericalCoordinates omitted entirely (JSON cannot carry NaN and lon/lat are undefined for a zero vector). Canonical ordering here is what makes the API's deterministic ordering requirement (003 §17) achievable.

## Task

Implement the AstronomyEngine over the four V1 models: model dispatch via the body registry, frame composition (heliocentric → geocentric by subtraction, ecliptic → equatorial by obliquity rotation), heliocentric Moon composition, degenerate origin handling, spherical coordinate derivation per frame, canonical ordering and the error contracts. Add the cross-frame consistency tests from 006 §14. Keep the engine free of HTTP, caching and any presentation concern.

## Acceptance criteria

- [ ] All 33 (body, frame) combinations return a CelestialState without throwing, for instants across the supported range
- [ ] The Sun in HELIOCENTRIC_ECLIPTIC and the Earth in both GEOCENTRIC_* frames return an exact zero position vector, distance {value: 0, unit: 'AU'}, and no sphericalCoordinates field at all
- [ ] The Moon in HELIOCENTRIC_ECLIPTIC is composed as Earth heliocentric + geocentric Moon, and a test asserts the composed heliocentric Moon minus Earth's heliocentric position reproduces the geocentric Moon state exactly
- [ ] Geocentric planetary states are computed as target heliocentric − Earth heliocentric using the coordinates subsystem's translation primitive
- [ ] GEOCENTRIC_EQUATORIAL states are produced by rotating the geocentric ecliptic state through the epoch-dependent obliquity, never by a body-specific path
- [ ] Each returned state carries the correct per-body modelId from the registry, its reference frame, its instant, and accuracy metadata; velocity is always undefined
- [ ] Spherical coordinates appropriate to the frame are attached: ecliptic longitude/latitude for ecliptic frames, right ascension/declination for the equatorial frame, all in degrees
- [ ] Unknown body → UnsupportedBodyError; unknown frame → UnsupportedReferenceFrameError; out-of-range instant → UnsupportedDateRangeError; all raised before any computation begins
- [ ] getStates returns bodies in canonical registry order regardless of input order and is equivalent to mapping getState over the list (asserted by test)
- [ ] The engine is pure: no caching that changes results, no wall-clock reads, no mutable module state; determinism test runs the same request twice and compares deeply
