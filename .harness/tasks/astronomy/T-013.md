## Context

ADR-013 and 002 §15 make the Moon a separate subsystem because it needs different corrections and materially different geocentric behaviour. The tutorial notes the unperturbed lunar model errs by degrees, so the perturbation stage is the whole point and must be provably active — hence the toggle-and-compare test. Heliocentric Moon states are composed later by the engine (Earth heliocentric + geocentric Moon), not here.

## Task

Implement the lunar subsystem under SCHLYTER_MOON_V1: base orbital state from the lunar elements, the tutorial's perturbation corrections as an isolated and toggleable stage, and the resulting geocentric ecliptic state with distance. Cite every term. Reserve but do not implement the topocentric stage. Do not compose heliocentric Moon positions here.

## Acceptance criteria

- [ ] The required stages are separately exported and separately tested: base lunar orbital state, perturbation corrections, geocentric state; the topocentric stage is explicitly deferred with a documented extension point
- [ ] The perturbation stage can be disabled for testing, and a test demonstrates the unperturbed model differs from the perturbed model by roughly the order of magnitude the tutorial describes (degrees vs arcminutes), proving corrections are actually applied

- [ ] Geocentric ecliptic longitude, latitude and distance are produced, with distance in AU and also available in km through an explicit conversion

- [ ] The tutorial's worked lunar example is reproduced as a committed test
- [ ] Determinism and purity tests pass
