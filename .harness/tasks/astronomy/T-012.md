## Context

The documents disagreed on Pluto's V1 status; the answered questions resolved it as in-scope with its own model ID, its own validity range, its own tolerance, and rendered like the planets. Schlyter's Pluto formula is a separate periodic-term expression, not an element set, so it does not go through the standard element table.

## Task

Implement Pluto's position model as its own module under SCHLYTER_PLUTO_V1, using the tutorial's dedicated formulation. Record its narrower validity range in its accuracy metadata and document why its accuracy is tracked separately from the major planets. Add plausibility and determinism tests.

## Acceptance criteria

- [ ] Pluto returns a heliocentric ecliptic Cartesian position and distance in AU with modelId SCHLYTER_PLUTO_V1
- [ ] The model uses Schlyter's dedicated Pluto formulation rather than the shared major-planet element table, and this choice is documented
- [ ] The model's stated validity range (1800–2100) is recorded in its accuracy metadata; requests outside the project range 1900–2100 are already rejected upstream, and a test confirms Pluto is available across the whole project range
- [ ] Heliocentric distance across sampled dates 1900–2100 falls within Pluto's known perihelion/aphelion bounds (~29.7–49.3 AU)
- [ ] Every equation and constant cites its tutorial section
- [ ] Determinism and purity tests pass
- [ ] Pluto's accuracy is documented as tracked separately from SCHLYTER_PLANETS_V1 with its own tolerance
