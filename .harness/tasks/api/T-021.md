## Context

The API is an adapter (003 §1) and the dependency direction is one-way (003 §20). The answered questions fixed V1 as local/self-hosted only, so CORS is localhost plus an env var and rate limiting ships implemented but off. The error taxonomy is the piece every subsequent endpoint task depends on, so it lands here rather than being invented three times.

## Task

Build the Express application skeleton with the 003 §19 structure, the health endpoint, the security middleware stack (CORS allowlist, body size limit, security headers, optional rate limiting), structured logging, and the centralised error handler that maps domain errors and Zod validation failures onto the fixed status/code taxonomy. Add tests for each error path and for production stack-trace suppression. Implement no ephemeris logic.

## Acceptance criteria

- [ ] GET /api/v1/health returns { status: 'ok', version, apiVersion: 'v1' } with 200
- [ ] The directory structure follows 003 §19: app.ts, server.ts, routes/, controllers/, schemas/, middleware/, errors/, serializers/
- [ ] A single error-handling middleware produces the 003 §13 envelope { error: { code, message, details } } for every failure path; no route returns an ad-hoc error shape
- [ ] Status mapping is implemented and tested: 400 for malformed/unparseable input, 404 for unknown routes, 413 for oversized batch requests, 422 for well-formed but semantically unsupported requests (out-of-range date, unsupported body/frame), 429 for rate limiting, 500 for internal and convergence failures
- [ ] Kepler convergence failures return 500 with code NUMERICAL_CONVERGENCE_FAILURE and are logged server-side; the client-facing message contains no stack trace or internal path
- [ ] Stack traces are never included in responses when NODE_ENV is production, asserted by test
- [ ] CORS allowlist defaults to localhost origins and is extendable via an environment variable; a disallowed origin is rejected
- [ ] Rate limiting middleware is implemented and disabled by default, enabled by an environment variable, and returns 429 with the structured envelope when tripped
- [ ] Security headers and a request body size limit are applied
- [ ] Logging distinguishes request errors, validation errors, astronomy calculation errors and unexpected internal errors, and does not log excessive numerical state
- [ ] The app imports packages/astronomy but packages/astronomy does not import anything from apps/api, enforced by the dependency-boundary check
- [ ] No astronomical equation appears anywhere in apps/api
