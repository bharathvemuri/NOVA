## Context

The answered questions made this endpoint the single source for the UI's body-info panel and for the renderer's client-side spin derivation, so the orientation constants must cross the wire here rather than per-instant on the ephemeris response. Determinism matters because E2E tests and the info panel both read it.

## Task

Implement the bodies endpoint as a thin serializer over the astronomy body registry, including the IAU orientation block, with a Zod response schema exported for the client. Add tests for completeness, ordering, unit presence and determinism.

## Acceptance criteria

- [ ] The response contains all eleven bodies in canonical registry order
- [ ] Each entry carries id, displayName, type, parentBody, radius {value, unit}, mass {value, unit}, supportedFrames, modelId, accuracy metadata and supportedDateRange
- [ ] Each entry carries the orientation block { poleRightAscensionDeg, poleDeclinationDeg, primeMeridianW0Deg, rotationRateDegPerDay, epochJulianDate } with the frame (J2000 equatorial) stated in the payload or its documented schema
- [ ] Every scientific quantity in the response has an explicit unit
- [ ] The response is validated against a Zod schema in a test, and the same schema is exported for client use
- [ ] The response is deterministic: two calls produce identical bodies (no timestamps, no random ordering)
- [ ] Body IDs are returned uppercase
- [ ] The endpoint reads the registry and performs no calculation
