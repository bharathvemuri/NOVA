## Context

ADR-010 makes this the single documented boundary where scientific coordinates become scene coordinates — 004 §5 and 001 §29 both demand the transformation be written down mathematically, and neither document ever did. The answered questions fixed the mapping, the scale constants, and resolved the Earth–Moon conflict (at 50x radii with true distances the Moon's mesh sits inside Earth's, so its orbital distance is exaggerated 8x in visualization mode only). Because R3F owns meshes in apps/web, this package is deliberately mesh-free.

## Task

Implement the coordinate adapter and scale system in packages/renderer as pure, WebGL-free functions: astronomy ecliptic → scene axis mapping, AU → scene units, physical radius → display radius per mode, and the parent-relative Earth–Moon distance override. Document the transformation mathematically. Add the round-trip, immutability and mesh-radius invariant tests. Add no meshes and no React.

## Acceptance criteria

- [ ] The axis mapping is implemented exactly as scene.x = astro.x, scene.y = astro.z, scene.z = −astro.y, documented mathematically in the module header including the handedness argument and why prograde motion appears counter-clockwise viewed from +Y
- [ ] The distance scale is 1 AU = 100 scene units, exposed as a configurable constant rather than a literal sprinkled through the code
- [ ] Display radius is derived from physical radius through the scale system and never by mutating physical metadata; a test asserts the input metadata object is unmodified
- [ ] Visualization mode multiplies body radii by exactly 50, with the Sun capped at exactly 5; scientific mode uses 1x for both radius and distance
- [ ] The Earth–Moon visualization override multiplies the Moon's parent-relative distance by exactly 8 in visualization mode only and exactly 1 in scientific mode; it is implemented as a parent-relative rule keyed by body so future satellites can reuse it
- [ ] An invariant test asserts that for every body in both modes, mesh radius ≤ 20% of the scene distance to its parent body, evaluated across sampled dates including lunar perigee
- [ ] Round-trip test: scene → astronomy → scene recovers the input to a documented tolerance, and the adapter is a pure function of its inputs
- [ ] packages/renderer contains no Three.js mesh, material, geometry or React component — it is adapter, scaling and coordinate logic only, enforced by the dependency-boundary check
- [ ] All exported functions are pure and independently testable without a WebGL context
