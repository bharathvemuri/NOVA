## Context

ADR-019 and 006 §7 make reference data test infrastructure: Horizons → fixture → commit → CI regression, with no network in CI. The answered questions fixed the exact Horizons configuration (body centres, not barycentres; VECTORS with no corrections, matching the geometric-only V1 model) and the fixture grid (30-day sweep for tolerance derivation, 100 committed dates for CI). Getting the centre/target codes wrong would silently poison every accuracy number in the project.

## Task

Write the committed fixture generation script with the fixed Horizons configuration, full provenance recording, both grid modes, and deterministic output. Document how and when to regenerate fixtures, and why regeneration must be intentional. Do not wire it into any test or CI job.

## Acceptance criteria

- [ ] scripts/generate-fixtures queries the JPL Horizons API and writes fixtures to tests/fixtures/ephemeris/ in a documented, versioned JSON format
- [ ] Horizons configuration is exactly: VECTORS product with corrections=NONE; centre 500@10 (Sun body centre) for heliocentric fixtures and 500@399 (Earth body centre) for geocentric fixtures; targets are planet body centres (e.g. 599 for Jupiter, not system barycentre 5)
- [ ] Each fixture record includes source, retrieval date, target body, observer/centre, frame, epoch, time scale, expected values with units, and the full literal query configuration used
- [ ] The script supports generating both the dense sweep (one instant every 30 days across 1900-01-01 to 2100-01-01 per body, ~2400 points) and the fixed 100-date CI subset, with the CI subset selection rule deterministic and documented
- [ ] Only the 100-date CI subset is committed to the repository by default; the dense sweep output path is gitignored and its regeneration is documented
- [ ] Running the script is never triggered by CI or by any test; a CI check asserts no test performs network I/O
- [ ] Re-running the script with the same arguments produces byte-identical fixture files apart from the recorded retrieval date
- [ ] The script is rate-limit-aware and resumable, and fails loudly on a partial or malformed Horizons response rather than writing a truncated fixture
