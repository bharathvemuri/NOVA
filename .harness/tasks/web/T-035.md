## Context

001 §34 forbids one giant global state object and 004 §20 fixes the React/Three.js division of labour. The answered questions pinned the first-load defaults (needed for E2E determinism together with URL state) and the fail-loud failure policy: pause plus a banner naming the error code, full-screen error on initial-load failure. V1 is local/self-hosted, so the API base URL is env-configurable.

## Task

Compose the application shell: the layout hosting the scene, controls, info panel and status bar; the four separated state stores; the frame switcher, mode toggle and layer toggles; the dev-only diagnostics panel; and the failure UX (pause-and-banner mid-session, full-screen retry on initial-load failure). Apply the fixed first-load defaults.

## Acceptance criteria

- [ ] First load defaults are exactly: HELIOCENTRIC_ECLIPTIC frame, visualization mode, current browser time, paused, all eleven bodies visible, orbit paths on, labels on
- [ ] A reference-frame switcher offers the three V1 frames; switching re-requests state in the new frame and triggers orbit regeneration, without resetting camera focus/tracking
- [ ] A rendering-mode toggle switches scientific ↔ visualization and provably leaves astronomy state unchanged
- [ ] Toggles exist for orbit paths and labels
- [ ] State is separated into astronomy, simulation, camera and UI stores rather than one global object, per 001 §34, and a review-checkable boundary is documented
- [ ] A mid-session API failure pauses the simulation clock and shows a dismissible banner naming the API error code and a human-readable message
- [ ] An initial-load failure shows a full-screen error with a retry action rather than an empty scene or a stale state
- [ ] A development-only diagnostics panel exposes simulation time, reference frame, body count, calculation/request latency, render FPS, selected body, camera mode and playback rate, hidden behind a dev flag
- [ ] The API base URL is configurable by environment variable and defaults to the local development API
- [ ] Component tests cover the default state, frame switch, mode switch, banner on failure and full-screen error on initial-load failure
