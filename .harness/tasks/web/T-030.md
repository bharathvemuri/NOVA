## Context

The orbit rules are heavily constrained by earlier answers: a full period is impossible for Neptune/Pluto inside a 200-year supported range, hence the 30-year cap; geocentric retrograde structure aliases badly at 360 samples over 30 years, hence the 5-year geocentric window; and regenerating an 11×360-instant sample set continuously during playback would flood the API, hence suppression while playing.

## Task

Implement the orbit layer: per-body server-side sample generation via the batch endpoint with the frame-dependent window and clamping, line geometry construction through the coordinate adapter, origin-body exclusion, the Earth-parented Moon loop with its visualization override, the pause/jump/frame-switch regeneration policy, the global toggle, and disposal on regeneration. Compute no positions client-side.

## Acceptance criteria

- [ ] Each path uses exactly 360 samples over a window of min(orbital period, 30 years) in heliocentric frames and min(orbital period, 5 years) in geocentric frames
- [ ] The window is centred on the current instant and clamped to 1900-01-01/2100-01-01, drawing a truncated arc near the range edges rather than erroring
- [ ] Samples are requested from POST /api/v1/ephemeris/batch, one request per body, in the currently selected frame — no orbit position is computed in the browser
- [ ] Geocentric paths are sampled in the geocentric frame and therefore show apparent retrograde loops; a visual/geometry test confirms Mars' geocentric path contains retrograde structure
- [ ] The origin body is excluded from the orbit layer per frame: no Sun path in heliocentric, no Earth path in geocentric
- [ ] The Moon's path is drawn as a geocentric loop parented to Earth's scene position in every frame, and in visualization mode it uses the same 8x parent-relative exaggeration as the Moon's mesh so the loop passes through the mesh position
- [ ] Regeneration is suppressed while playing: paths regenerate on pause, on explicit date jump, and on frame switch only; the drawn window is allowed to drift off-centre during playback
- [ ] Orbit generation is decoupled from body meshes — a failure to fetch a path leaves the bodies rendering
- [ ] Orbit paths can be toggled globally and default to on
- [ ] Line geometries are disposed on unmount and on regeneration; renderer.info counts do not grow across repeated regenerations, asserted by test
