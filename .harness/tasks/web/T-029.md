## Context

004 §30 requires astronomy coordinates to pass through exactly one documented adapter and both rendering modes to preserve domain state. The answered questions moved the §9 presentation registry into apps/web (R3F owns meshes) and put spin derivation client-side from /bodies metadata so the per-instant payload stays unchanged. The Moon's 8x visualization override must be applied consistently — mesh, and later orbit loop, label anchor and pick proxy — or the artifacts disagree.

## Task

Render the eleven bodies as R3F components driven by interpolated engine states through the coordinate adapter, with the presentation registry, textures, lit standard materials, mode-dependent display radii, the Earth-parented Moon with its visualization distance override, and client-derived axial spin from the /bodies orientation metadata. Add the mode-switch immutability test and the disposal/leak test. Do not compute any position in the renderer.

## Acceptance criteria

- [ ] A presentation registry in apps/web maps BodyId to mesh factory, texture, material and label; it is presentation metadata only and contains no physical constants (those come from GET /api/v1/bodies)
- [ ] Body positions are produced by passing engine states through packages/renderer's coordinate adapter; no ad-hoc axis swap or unit conversion exists in any component
- [ ] Display radii use the scale system: 1x in scientific mode, 50x in visualization mode with the Sun capped at 5x
- [ ] Axial spin is derived client-side from the /bodies orientation metadata plus the current instant using the astronomy package's documented pole-to-ecliptic-of-date rule, mapped into scene axes by the adapter; Earth's axis visibly tilts ~23.4° and its rotation phase is absolute rather than arbitrary
- [ ] The Moon is parented to Earth's scene position; in visualization mode its parent-relative distance is exaggerated exactly 8x and in scientific mode exactly 1x
- [ ] In geocentric frames the Earth sits at the scene origin and all other bodies are positioned relative to it; switching frames changes only scene positions and never mutates or refetches under a different interpretation of the same state
- [ ] Mode switching (scientific ↔ visualization) changes only display radii and the Moon override; a test asserts the underlying state objects are byte-identical before and after the switch
- [ ] Textures load from the CC-BY Solar System Scope set with attributions in THIRD_PARTY_ASSETS, and a missing texture degrades to a flat colour rather than crashing the scene
- [ ] Unmounting the scene disposes every geometry, material and texture; renderer.info geometry/texture counts return to baseline, asserted by test
