## Context

006 §23 allows E2E to run in a separate CI stage because browser execution is expensive. The 'current browser time' default made deterministic E2E impossible until URL state landed, which is why this task depends on T-036. Visual regression is explicitly deferred until the visual system stabilises (006 §18).

## Task

Write the Playwright E2E suite covering the ten core scenarios, driven from pinned URLs against a real API instance, with deterministic time assertions and no pixel comparisons. Wire it as a separate CI stage across the three supported desktop browsers, failing on console errors.

## Acceptance criteria

- [ ] Scenarios covered: application loads; default solar system appears; date changes; time advances; time reverses; a planet is selected; camera focuses; tracking works; orbital paths toggle; visualization mode toggles
- [ ] Every scenario navigates to a pinned URL carrying an explicit instant so no assertion depends on wall-clock time
- [ ] Tests run against the real Express API (started by the test harness), not a stubbed fetch layer
- [ ] Time-advance and time-reverse assertions compare exact simulation instants using the clock's injectable time source or a deterministic wait, not loose ranges
- [ ] Selection and focus assertions verify the selected body ID and the camera's settled distance relationship rather than pixel comparisons
- [ ] The suite runs in current desktop Chrome, Firefox and Safari (WebKit) on Node 20
- [ ] The E2E stage is a separate CI job from the unit/domain/API gates and is green
- [ ] Tests fail loudly on any console error or unhandled rejection during a scenario
- [ ] No pixel-perfect visual regression assertions are introduced
