## Context

At the home view Earth's true-scale mesh is ~0.0043 scene units — far below a pixel — so without pick proxies selection would be impossible in scientific mode and 006 §19's E2E selection scenario could not pass. Overlapping proxies are the normal case at that zoom, hence the explicit tie-break. Click-selects-only (focus is a separate action) is a fixed decision from the camera answer.

## Task

Implement selection: invisible screen-space-sized pick proxies on a dedicated raycast layer, billboard markers for sub-pixel bodies, the deterministic nearest-angular-offset tie-break with its documented fallbacks, empty-space clearing, and the body info panel fed by the bodies endpoint plus live ephemeris values with explicit units and the visualization-mode divergence note. Keep selection state separate from camera state.

## Acceptance criteria

- [ ] Every body carries an invisible pick-proxy sphere sized to a minimum screen-space radius of ~12 px in both scientific and visualization modes, and a screen-space billboard marker keeps sub-pixel bodies visible in scientific mode
- [ ] Only pick proxies participate in the selection raycast layer; body meshes, orbit lines, labels and the skybox do not
- [ ] When multiple proxies are hit, the winner is the body with the smallest angular offset between the pointer ray and the body centre; ties break by nearest to camera, then by canonical registry order — asserted by a unit test with contrived overlapping configurations
- [ ] Selection is deterministic: the same pointer position and camera state always select the same body
- [ ] A single click selects only; it does not move the camera
- [ ] Clicking empty space clears the selection
- [ ] The Moon's pick proxy uses its rendered position including the 8x visualization override
- [ ] The info panel renders from GET /api/v1/bodies metadata (displayName, type, parent, radius, mass, model ID, accuracy, supported date range) plus the live ephemeris values (position, distance, spherical coordinates) with units shown for every quantity
- [ ] The panel shows a note explaining that in visualization mode the Moon's rendered direction/separation is exaggerated and differs from the reported ecliptic coordinates
- [ ] Selection state is stored separately from camera state; changing one does not implicitly change the other, asserted by test
