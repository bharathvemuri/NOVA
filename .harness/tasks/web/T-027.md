## Context

ADR-017 requires simulation time independent of wall-clock time, and the answered questions specified the anchor-based formulation precisely so the E2E 'time advances / time reverses' scenarios can assert exact values rather than loose ranges. The rate cap and the dropped 1 year/sec preset come from the prefetch window arithmetic in T-026.

## Task

Implement the simulation clock as an anchor-based, injectable-time-source state machine with the fixed rate convention, presets, range clamping with auto-pause, and change events. Keep it free of fetching, rendering and React-specific concerns so it can be unit-tested headlessly.

## Acceptance criteria

- [ ] The clock computes instant = anchorInstant + playbackRate × (now − anchorRealTime), and re-anchors on every rate change, direction change, pause, resume and date jump
- [ ] The time source is injectable so tests advance it deterministically; no direct Date.now() call exists outside the default time source
- [ ] playbackRate is simulation-seconds per real-second (86400 = 1 day/sec) and its sign carries direction; this convention is documented in the module header and surfaced in the UI copy
- [ ] Rate presets are 1 s/s, 1 min/s, 1 hr/s, 1 day/s and 1 month/s; 1 year/s is absent and the maximum enforced rate is 1 month/s
- [ ] Reaching either edge of the supported range (1900-01-01 / 2100-01-01) clamps the instant to the boundary and auto-pauses, asserted by test in both directions
- [ ] Frame rate and dropped frames do not affect the computed instant: advancing the injected time source by a fixed amount in one step and in many small steps produces identical instants
- [ ] The clock exposes { currentInstant, playbackRate, direction, paused } and emits change events; it performs no fetching and no rendering
- [ ] Unit tests cover play, pause, resume, reverse, rate change mid-playback, jump, and both range boundaries
