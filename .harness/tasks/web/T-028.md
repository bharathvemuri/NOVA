## Context

The answered questions chose React Three Fiber inside apps/web and superseded 004 §8's imperative PlanetRenderer interface — mesh lifecycle is the component tree's job. packages/renderer stays mesh-free. The scale, zoom bounds and home view come from the accepted defaults; the logarithmic depth buffer is what makes a 0.05–20000 unit range survivable.

## Task

Build the R3F canvas host and scene skeleton in apps/web: the layered scene graph, orbit/pan/zoom camera controls with the fixed zoom clamp and home view, logarithmic depth buffer with per-zoom near/far tuning, the Sun mesh plus separate point light, and the static skybox. Establish the render-loop pattern that avoids per-frame React state updates. Render no planets yet.

## Acceptance criteria

- [ ] The scene graph contains SolarSystemRoot, OrbitLayer, LabelLayer, SelectionLayer and DebugLayer as distinct groups, even where empty
- [ ] The camera supports orbit, pan and zoom via pointer drag, wheel and pan gesture/button, with zoom clamped to [0.05, 20000] scene units
- [ ] A logarithmic depth buffer is enabled and near/far planes are tuned per zoom level; a test or manual check confirms no z-fighting between Mercury's orbit region and Neptune's at the home view
- [ ] The default home view frames Neptune's orbit, and a reset/home action returns to it
- [ ] The Sun is rendered as a mesh plus a separate point light object; the light object is not consulted by any state calculation, and a test asserts light parameters never feed back into position data
- [ ] Bodies use MeshStandardMaterial lit by the Sun point light so phases and a terminator are visible; shadow maps are disabled
- [ ] A single static equirectangular starfield/Milky Way skybox from the CC-BY Solar System Scope set is applied as the scene background, with its attribution recorded in THIRD_PARTY_ASSETS
- [ ] React state is not updated on every animation frame; the render loop reads from refs/stores, asserted by a test or an explicit documented pattern
- [ ] The scene mounts and unmounts cleanly with no console errors under React StrictMode double-invocation
