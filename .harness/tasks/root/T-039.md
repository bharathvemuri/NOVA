## Context

V1 is local/self-hosted per the answered questions, so rate limiting ships disabled by default and no auth is required — but the middleware must exist and be tested so public exposure is a config change, not a rewrite. 006 §23 makes numerical regression tests a mandatory gate, which this task confirms is actually wired.

## Task

Conduct and document the security review across the Express surface and the browser app, verify the middleware behaviours with tests, add dependency auditing and the dependency justification document, and confirm the full CI gate set from 006 §23 is enforced with E2E in its own stage. Record accepted risks explicitly.

## Acceptance criteria

- [ ] Every HTTP input is validated by a runtime schema at the boundary; a review checklist confirms no route reads an unvalidated query or body field
- [ ] CORS allowlist, request size limits, security headers and the (default-off) rate limiter are verified by tests, including a rejected cross-origin request and a tripped rate limit returning 429
- [ ] Production responses contain no stack traces or internal paths, verified by test with NODE_ENV=production
- [ ] The frontend performs no unsafe HTML rendering, validates all API responses against shared schemas before use, and loads assets only from the documented origins
- [ ] A dependency audit runs in CI and fails on high-severity advisories; every direct dependency is justified in a dependencies document with reason, alternatives considered, license and maintenance assessment per 005 §11
- [ ] Dependency versions are locked and the lockfile is committed
- [ ] CI enforces the complete required gate set: typecheck, lint, unit tests, domain tests, API tests and the numerical regression suite, with E2E as a separate stage
- [ ] A security review document is committed listing what was reviewed, what was found, what was fixed and what was accepted as out of scope for a local/self-hosted V1
- [ ] No authentication is introduced (out of scope for V1)
